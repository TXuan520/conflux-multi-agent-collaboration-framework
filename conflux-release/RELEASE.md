# Conflux v0.1.0 · 首个公开版本

本机运行的多智能体协作台：让人类总指挥和多个异构 AI 成员坐在同一条时间线上干活、争论、交付。

这不是又一个聊天框。它解决的是「多个模型怎么在一张桌上分工」——消息路由、点名、广播、打包投递、工单流转、发布门禁，都在这一层。

---

## 这版能做什么

**1. 同席协作，不是轮流单聊**

- 消息按待回复关系自动回投给提问者，重启不串台
- 用独立行 `>>> 成员名` 精准点名，一轮里可以同时点多人，自动拆条并发
- 人类消息逐条直达；成员之间按收件人打包投递，满 3 条或超时放行，避免消息风暴

**2. 两种工作模式**

- **常规模式**：按职责点对点协作，工单驱动，状态可查
- **广播模式**：全员互通，鼓励交锋；纯「收到/OK」在程序层被拦截，不占带宽；可以 `[[silent]]` 选择性沉默

**3. 多端接入**

本地脚本循环、Codex、Antigravity、豆包、WorkBuddy、MiMo，各自独立通道；也支持填 OpenAI / Anthropic 兼容接口，热插拔增删成员，不用重启。

**4. 工程门禁**

- 文件读写分级：敏感目录禁读禁写，高危命令拦截，写入走原子替换
- 发布门禁 `release-gate.py`：扫 API Key、Token、QQ 号、本机绝对路径、云 IP，命中即 BLOCKED
- 演示模式 `--demo`：用隔离的假数据跑，不碰真实记录

## 怎么跑起来

```
要求：Python 3.11+，无需安装第三方依赖
```

Windows：

```
双击 start.bat
```

macOS / Linux：

```
bash start.sh
```

浏览器打开 `http://127.0.0.1:8777`。

想看演示效果、不想接真实模型：

```
python scripts/hub.py --demo
```

## 已知限制（说在前面）

- **不接模型也能启动，但没有成员干活**。各通道要单独配，DeepSeek/Codex 等桥接属于可选扩展。
- **广播模式的分包是我按「每个收件人独立计 3 条」实现的**，和早期文档里写的「按人数 N-1」不一致，以实际行为为准。
- **工单四栏流转已经跑通，但真实业务里的长任务还没验证过**。0.1.0 只保证机制可用，不保证扛住复杂项目。
- **Windows 上偶发文件占用（WinError 32）**，会自动降级到备用通道，不影响使用但会变慢。
